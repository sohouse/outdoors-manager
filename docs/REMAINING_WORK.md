# Remaining Work

## 当前判断

现阶段“代码功能改造”可以暂时收一段，重点已经从“把功能做出来”切到“把项目变成稳定、可讲、可继续扩展的样本”。

## 接下来最值得做的事情

### 1. 统一前端 API 调用切面

目标：

- 页面不再分散处理 `ApplicationResponse`
- 页面不再分散维护重复的错误弹窗逻辑

建议产物：

- API facade
- 全局错误提示 provider
- 通用异步 action hook

### 2. 梳理文档与方案记录

目标：

- 让 README、产品目标、架构说明、剩余工作彼此对齐
- 为关键改造保留 plan 文档和决策记录

### 3. 继续强化面试材料

目标：

- 让项目介绍、demo、深问回答更熟练
- 从“写过代码”升级到“能讲清设计取舍”

### 4. 再扩一个强相关业务模块

候选方向：

- 我的活动
- 订单管理
- 车辆管理
- 领队管理

## 不建议现在做的事

- 和当前业务弱相关的 RAG 或 AI 能力硬集成
- 同时起多个新模块导致主线失焦
- 为了“重构而重构”去大面积改动稳定代码

## 推荐执行顺序

### 第一阶段

- 完成前端 API 解析与错误提示统一
- 为这次改造补一个 plan 文档

### 第二阶段

- 练 demo 和项目讲述
- 根据面试反馈调整文档和说法

### 第三阶段

- 增加一个强相关新模块
- 让权限和接口设计跨模块复用

## 完成判定

如果以下条件成立，可以认为当前阶段完成得比较好：

- 页面层不再重复 `unwrapResponse + setErrorInfo + ErrorAlert`
- 文档结构完整且易导航
- 项目介绍和架构说明可以稳定输出
- Activity 模块仍然是清晰、可讲、可验证的主样本
